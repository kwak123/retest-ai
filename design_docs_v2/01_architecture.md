# Architecture Overview

## System Context
`retest-ai` is an MCP (Model Context Protocol) Server that acts as a testing companion for AI Coding Agents (like Claude, Cursor, Gemini). It provides a persistent memory of test generation (prompts -> tests) and a mechanism to execute text-based testing commands.

## Components

### 1. **MCP Server (Node.js)**
- **Role**: The core process running locally on the user's machine.
- **Libs**: `@modelcontextprotocol/sdk`
- **Responsibilities**:
  - Expose Tools to the connected Client (Agent).
  - Manage in-memory state of tests and prompts.
  - Read/Write to `retest-ai.index.json` (persistence).
  - Spawn child processes to run tests (e.g., `npm test`).
  - Serve the Web UI.

### 2. **Language Services (Parsers)**
- **Role**: Understanding the structure of test files to track individual tests.
- **Strategy**: Language-specific modules.
- **Modules**:
  - **JavaScript/TypeScript**: Uses `acorn` or `typescript-estree` to identify `describe`, `it`, `test` blocks.
  - **C#**: (Future) Uses Roslyn or similar.
- **Workflow**:
  - Input: File Content.
  - Output: List of Test Definitions is `{ name, body, location, code_hash }`.

### 3. **Persistence Layer (File System)**
- **Path**: `.retest/retest-ai.index.json`
- **Role**: Stores the mapping of:
  - Application Source Files <-> Test Files
  - Test File -> Test Suites -> Individual Tests
  - Test -> Last Prompt Hash & Code Hash
  - Prompt Hash -> Prompt Content
- **Future**: SQLite or similar, but JSON for MVP.

### 4. **Web UI (Localhost)**
- **Role**: A simple visual dashboard for the user to inspect the state of their tests.
- **Tech**: HTML/JS served by the MCP Server (Express or similar).
- **Features**:
  - List all tracked test files.
  - Expand files to see individual tests.
  - Show "Prompt History" for each test.
  - "Re-run" button (triggers MCP execution).

## Data Flow

1.  **Agent Generates Test**:
    - Agent calls `record_test_generation(file, prompt)`.
    - MCP Server detects language (e.g. `.ts`).
    - **Parser** extracts all tests from the new file content.
    - MCP Server hashes the code body of each test.
    - Updates `index.json`:
      - If test is new: Add it with current `prompt`.
      - If test exists and `code_hash` changed: Update `prompt` and `code_hash`.
      - If test exists and `code_hash` is same: Do nothing (or update timestamp).

2.  **User Views History**:
    - User opens Web UI.
    - UI fetches structured test data.
    - User expands a file to see which specific tests were generated by which prompt.

3.  **Refactor/Retry**:
    - Agent calls `get_test_info(file)`.
    - MCP returns list of tests and their prompts.
    - Agent targets a specific test to rewrite.

## Security
- Runs as a local process with user permissions.
- Only localhost access for Web UI.
